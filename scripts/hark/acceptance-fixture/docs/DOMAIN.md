# 小店库存模块 — 业务规则（DOMAIN）

本文件是库存模块的唯一业务规则来源。代码与测试都必须以这里为准；规则编号在代码注释和测试名里引用。

## 背景
这家文具小店有一个线下门店和一个小程序。库存数据每天晚上从收银系统导出一次，由这个模块计算库存价值和第二天的补货计划。补货计划会发给两家供应商，供应商按"包装单位"发货，所以下单数量必须是包装单位的整数倍。店主希望系统"宁可多订一点，也不要断货"，但已经下架（discontinued）的商品绝对不能再订。

## 数据字段
- sku：商品编码，字符串，唯一。
- name：商品名称（中文）。
- qty：当前库存，非负整数。
- price：单价（元），最多两位小数。
- reorderPoint：补货点。库存**严格低于**补货点时才需要补货；等于补货点不补。
- targetStock：目标库存。补货后希望达到的库存量。
- minOrder：最小起订量。供应商要求单次至少订这么多。
- packSize：包装单位，正整数。
- discontinued：可选布尔值；为 true 表示已下架。

## 规则
- R1 入库：同一 sku 再次入库时数量累加，不新建条目。数量必须是非负整数。
- R2 出库：出库后库存不能为负数。出库数量大于当前库存时抛出 RangeError，并且库存保持不变（不允许部分扣减）。
- R3 库存价值：totalValue() = 所有商品 qty × price 之和，结果四舍五入到分（两位小数）。
- R4 补货计划 reorderPlan(items)：输入为商品数组（字段同上），输出为数组，每个元素是 { sku, orderQty }，按 sku 字典序升序排列。
  - R4.1 只有 qty < reorderPoint 且 discontinued 不为 true 的商品进入计划。
  - R4.2 基础下单量 = max(minOrder, targetStock - qty)。
  - R4.3 下单量向上取整到 packSize 的整数倍（例如基础量 27、packSize 12 → 36）。
  - R4.4 不修改输入数组和其中的对象（纯函数）。
  - R4.5 输入为空数组时返回空数组。
- R5 reorderPlan 必须从 src/inventory.js 导出（module.exports.reorderPlan），不依赖任何第三方包。

## 示例（R4）
输入：
- { sku: 'C-300', qty: 2, reorderPoint: 10, targetStock: 40, minOrder: 10, packSize: 6 } → 基础量 max(10, 38) = 38 → 向上取整到 6 的倍数 = 42
- { sku: 'A-100', qty: 4, reorderPoint: 5, targetStock: 12, minOrder: 10, packSize: 5 } → 基础量 max(10, 8) = 10 → 10
- { sku: 'B-200', qty: 20, reorderPoint: 20, targetStock: 100, minOrder: 50, packSize: 12 } → 不补（等于补货点）
- { sku: 'D-400', qty: 0, reorderPoint: 3, targetStock: 9, minOrder: 1, packSize: 1, discontinued: true } → 不补（已下架）
输出：[ { sku: 'A-100', orderQty: 10 }, { sku: 'C-300', orderQty: 42 } ]
