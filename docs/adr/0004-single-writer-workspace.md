# ADR-0004：单一 Writer 工作区治理

> 归属：用户 STEP 1 裁定（Sprint 0 汇报审阅结论）；配套文档 `docs/WORKSPACE_GOVERNANCE.md`。

## 状态

**已接受（Accepted）** — 立即生效。

## 背景

Sprint 0 收尾期间，同一个仓库目录被**两个 Agent 会话并行写入**。实测证据：

- 同一次动作内连续读取 `docs/OPEN_SOURCE_RESEARCH.md`，得到 160 / 229 / 297 行三种不同内容；
- `git status --porcelain` 在空与非空之间反复变化；
- 一个已交付的文档被另一个会话覆盖（我方的调研报告被替换）；
- 两次 `git add -A` 之间出现了非本会话的改动。

后果是**验证失去意义**：`pnpm check` 只对某一瞬间的树成立，而该瞬间可能包含他人的半成品。

## 决策

1. **同一 Workspace 同一时间最多只能有一个 Writer Agent。**
2. **Reviewer 默认只读**（不得写任何文件）。
3. **QA 默认只读**；除测试自身产生的临时文件外不得修改源码。
4. 需要多个 Writer 并行时，**必须使用独立 Git Worktree**，禁止共享同一工作目录。
5. 发现来源不明的修改：**停止写入** → 列出差异 → 判断来源 → 交用户裁决。
6. **禁止**用 `git reset --hard` / `git clean -fd` 掩盖差异（需明确人工批准）。

完整规则、开工前的写入漂移采样命令、角色权限矩阵与隔离方案见 `docs/WORKSPACE_GOVERNANCE.md`。

同时在 `AGENTS.md` 增加 §1.5（工作区治理）与 §0.1（单一真相源），使该规则成为每一轮 Agent
的入口契约，而不只是一份说明书。

## 后果

**收益**：验证结论可信；提交内容可归因；不再出现"文件被谁改的说不清"。

**代价**：并行度下降。缓解方式是 §5 的分层：单 Writer 为默认；确实需要并行时用 Git Worktree
（每个 Writer 一个工作目录 + 一个分支），合并由用户或 Chief 决策。

**执行记录（Sprint 1 开工前）**：120 秒写入漂移采样 → 140 个文件 0 处变化、`git status` 为空、
`HEAD = 76d7bd733c7531f2ccb20d4cf29e0eb69a8312e9`。该窗口内无第二个 Writer 活动；但这只证明
"窗口内无写入"，不证明另一会话已终止，故本 ADR 的规则持续有效。
