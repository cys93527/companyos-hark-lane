# H17 — 普通用户真机验收清单（Hark lane）

本清单由 Hark 准备，**由用户本人在自己的 Windows 电脑上执行并填写结果**。Hark 不执行、不代填、不授予 PASS；Hark 侧只有 CI 上的 "Hark self-review PASS"。
对照：`pkg/handoff/PRODUCT_TARGET.md`、`COMPARISON_ACCEPTANCE.md`。结果只允许填 **PASS / FAIL / 未运行 / 受阻**，未运行或受阻不得改写成 PASS；每一项的结果只来自这一次真机执行，不与 CI 或以往次数累加。

## 0. 准备
| 项 | 要求 |
|---|---|
| 电脑 | Windows 10 22H2 或 Windows 11，x64；记录版本号（`winver`）、杀毒软件名称 |
| 账户 | 建议用**非管理员的标准用户**登录执行第 1–9 节；第 10 节（隔离）需要一次管理员密码 |
| 安装包 | 从 GitHub release 下载 `CompanyOS-Hark-Setup-<版本>-x64.exe` 与同页 `SHA256SUMS` |
| 模型 | 一个 DeepSeek API Key 和账户余额（建议预先在 DeepSeek 控制台设置用量提醒）；本清单的真实目标预计花费不超过 ¥4（以应用内显示和 DeepSeek 账单为准） |
| 样例工作区 | release 附带的 `shop-inventory` 样例目录（与 CI 验收 fixture `scripts/hark/acceptance-fixture` 逐字节相同），解压到例如 `D:\CompanyOS-验收\shop-inventory` |
| 记录 | 每项截图或复制错误文字；第 12 节列出需要回传的文件 |

## 10. 隔离（可选，需要一次管理员密码）
先在 CompanyOS 中选好工作区（第 4 节）。
| # | 步骤 | 预期 | 结果 | 证据 |
|---|---|---|---|---|
| 10.1 | 开始菜单 →「CompanyOS 隔离设置」，UAC 中输入管理员密码 | 窗口显示"已启用隔离（专用账户 CompanyOSAgent……，工作区 ……）"；`%APPDATA%\CompanyOS\isolation\` 下有 `state.json` 和 `agent-credential.dpapi`，没有 `handoff-*` 文件 | | |
| 10.1b | 开始菜单 →「CompanyOS 隔离状态」 | 显示"已隔离：智能体以专用账户 …… 运行"（不需要管理员） | | |
| 10.2 | 再跑附录 A 目标 | 结果同第 4 节；任务管理器 → 详细信息中内核 `node.exe` 的用户名为 CompanyOSAgent…… | | |
| 10.3 | 隔离状态下，若本机开着代理软件（如 127.0.0.1:7890） | 代理不会被内核使用（目标仍只经 CompanyOS 自己的通道访问 DeepSeek） | | |
| 10.4 | 在 CompanyOS 中换一个**新的**工作区再派发目标 | 目标失败，原因含 `ISOLATION_DEGRADED` / `workspace:notGranted`，**不会**以未隔离方式运行；重新运行「CompanyOS 隔离设置」后恢复 | | |
| 10.5 | 开始菜单 →「CompanyOS 移除隔离」（UAC） | 显示"已移除隔离"；`计算机管理 → 本地用户和组` 中不再有 CompanyOSAgent 账户；「CompanyOS 隔离状态」显示"未隔离"，之后目标以你的账户运行 | | |
| 10.6 | （可选）启用隔离后直接卸载 CompanyOS | 卸载时会请求一次管理员授权并移除隔离账户；卸载后无 CompanyOSAgent 账户残留 | | |

已知残留（不算失败，但请知悉）：DNS 查询不受隔离限制；其他磁盘根目录（如 D:\）对所有登录用户默认可读的内容，隔离账户也能读。

## 附录 A — 样例目标（与 CI 验收逐字相同）
工作区根目录是一个小型 Node.js 库存模块（shop-inventory，无第三方依赖），业务规则全部写在 docs/DOMAIN.md。请按顺序完成：1）阅读 docs/DOMAIN.md 和现有代码，修复 src/inventory.js 中导致 npm test 失败的缺陷（以规则 R2、R3 为准）；2）按规则 R4/R5 在 src/inventory.js 新增并导出 reorderPlan(items)，并新建 test/reorder.test.js，至少 3 个测试（覆盖文档中的示例、等于补货点不补、已下架不补）；3）运行 npm test 确认全部通过；4）新建 docs/CHANGES.md，用中文说明修复了哪些缺陷、reorderPlan 的规则和最终测试结果。不要引入任何第三方依赖，不要修改 docs/DOMAIN.md。
